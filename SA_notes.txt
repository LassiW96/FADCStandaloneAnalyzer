Standalone Analysis of MOLLER Data:

Standalone code piece has been imported from hcana and added in the
beginning of the MOLLERGenericDetector class. 

SetSampIntTimePedestalPeakStandalone is the relevent pulse selection
method. Lines 94 - 262.

Arguments that are taken in to the functions:
    const std::vector<Double_t>& samples (the raw digitized waveform, time ordered ADC counts),
    Int_t fNPedestalSamples (# of leading samples to estimate pedestal),
    Double_t fSampThreshold (pulse detection threshold value),
    Int_t fNSB (# of samps before thrsh crossing to include in the integral),
    Int_t fNSA (# of samps after thrsh),
    Int_t fNSAT (# of consecutive samps after thrsh crossing to consider as a good pulse),
    Int_t fMaxNPulses (Maximum allowed # of pulses per waveform)

106 - 113:
    Just assigning size of the variables in the "data" struct with 
    "fMaxNPulses" number of zeroes. 

fNSamples is the size of the samples vector. 

117 - 131:
    Three lambda functions (anonymous inline function).
    GetIntegral : Calculates the sum/integral of samples in a given range.
    GetSampleRaw : Gets the raw sample value at a given index.
    GetSample : Gets the pedestal subtracted sample value at a given index.

"data" is the member of the MOLLERTHcSampData struct.
fHasMulti (boolian for has multiple hits I guess), is already assigned
to kFALSE in the beginning. This is turned to kTRUE in line 133.

fSampPed is the sum of the first fNPedestalSamples to the samples, 
calculated using GetIntegral lambda. Line 134. This is not the exact pedestal 
value; this is just the integral/sum of ped samples. You have to scale it to 
subtract from the pulse value.

NS (# of total samples to calculate the ped I guess) is then adjusted to 
fNPedestalSamples - 1.

## -1s and +1s are because array indexing in c++ (arrays start at 0)

fNSampPulses is the number of sampled pulses in the waveform.

Lines 139 - 145: case if fSampThreshold == 0. 
    Abandons threshold crossing algorithm and assume there is a pulse right after
    NS and force integrate.
    Total window is integrated. 
    To get the fSampPulseInt (pulse integral I guess), sample is integrated from,
    (NS - fNSB) to the which ever minimum of (NS to fNSA -1) or the size of the sample
    vector.

    fNPeakSamples is the # of samples corresponding to the pulse peak.
    # of samples ended up inside the integration window. 

    fPeakPedestalRatio is the ratio btwn # of peak samples (as in the above) and
    the # of pedestal samples. 

    Then the pedestal substracted pulse integral.

Relevent other info:
The Standalone Analizer should be;
No Framework Dependencies: There are no framework-specific objects being passed in 
(e.g., no EventContext& event, no GeometryManager* geo, no RunDatabase& db).

Primitive Inputs: It relies only on standard C++ containers (std::vector) and primitive 
data types (using ROOT's Double_t and Int_t).

Injected Configuration: Instead of the function querying a database or an XML file to 
find out what the threshold (fSampThreshold) or integration window (fNSA, fNSB) should be, 
those values are passed directly as arguments.

Agnostic Output: It stores the results in a simple custom data structure (likely a 
struct containing integral, peak_time, pedestal_mean, etc.) rather than writing directly 
to a framework-specific output tree or event bus.
